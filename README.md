## О форке

Это **форк** оригинальной InstantCMS 1.x. Последняя официальная версия — 1.10.7 (2016) — давно не
развивается, при этом система востребована. Здесь она поддерживается и развивается дальше:
устраняются уязвимости и ошибки, обновляются библиотеки, улучшается интерфейс и установщик.

Исходная система создана командой InstantCMS (InstantSoft); права на неё принадлежат авторам,
форк распространяется под той же лицензией **GNU/GPL v2**.

### Что уже сделано в форке

- **Совместимость с PHP 8.2/8.3** — устранены фатальные ошибки и deprecated-конструкции
  (динамические свойства, устаревшие функции, порядок параметров); проверено запуском
  на публичных страницах и в панели управления.
- **Безопасность**
  - пароли — bcrypt (`password_hash`) с прозрачным обновлением старых md5-хешей при входе;
  - cookie «запомнить меня» подписана HMAC-секретом, а не вычислима из дампа базы;
  - устранён `unserialize()` пользовательской cookie (PHP Object Injection);
  - установщик автоматически отключает себя после установки;
  - обновлены библиотеки с известными уязвимостями (jQuery, CKEditor и др.).
- **Библиотеки**: Smarty 5.8, jQuery 3.7.1 (+ jQuery Migrate), jQuery UI 1.14, PHPMailer 6.12,
  GeSHi вычищен от `create_function`.
- **Визуальный редактор**: вместо CKEditor 4 (EOL, без обновлений безопасности) — **TinyMCE 8**
  (лицензия GPLv2+/коммерческая, используется открытая). Скин выбирается в настройках плагина.
- **Инсталлятор** переработан: пошаговый мастер, автоматическое создание базы данных при её
  отсутствии, проверка сложности пароля, определение прав доступа, тёмная тема.
- **Установочные дампы** адаптированы под строгий режим MySQL 5.7+/8 и MariaDB.

Планы: дальнейшая поддержка совместимости с новыми версиями PHP, аудит безопасности,
обновление оставшихся библиотек, развитие шаблонов и интерфейса.

## Требования

- Apache 2.4 + mod_rewrite (возможен nginx; правила — в комментариях к `.htaccess`)
- PHP **8.2+** с расширениями: GD, iconv, mbstring, mysqli, json, SimpleXML
- MySQL **5.7+** или **MariaDB 10.2+** (строгий режим SQL поддерживается)

> Система также запускается на PHP 7.x, но поддерживаемой и проверенной является ветка 8.2+.

## Установка

1. Распакуйте архив с системой в корень сайта (или клонируйте репозиторий).
2. Откройте `http://your-site.ru/install` — мастер проверит сервер и права на папки.
3. Укажите параметры MySQL. **Базу данных можно не создавать заранее** — отметьте создание,
   и установщик сделает её сам (нужны соответствующие права у пользователя MySQL).
4. Задайте название сайта, логин и пароль администратора.
5. После установки мастер сам переименует папки `install` → `_install` и `migrate` → `_migrate`,
   чтобы сайт не показывал страницу установки и их нельзя было запустить повторно.

Если нужно запустить установщик снова — верните папке прежнее имя (`_install` → `install`).

### Права на папки

При установке на хостинг установите права **777** на директории:

```
/cache
/images
/includes (только на время установки)
/upload
```

и все вложенные в них. На файлы `.htaccess` права должны быть **644**.

> **Важно:** если у вас shared-хостинг, директория хранения сессий должна быть своей для каждого сайта.

## Обновление

1. Сделайте резервную копию сайта и дампа базы данных — **обязательно!**
2. Распакуйте архив поверх существующих файлов, заменив их.
3. При необходимости выполните скрипт обновления: `http://your-site.ru/migrate`
   (папка `migrate` в исходном виде называется `_migrate` — верните имя).
4. Удалите (или переименуйте) папки `install` и `migrate`.
5. Очистите кеш: удалите файлы в `/cache` (кроме `.htaccess`) и кеш браузера.

## Структура каталогов

```
/admin/          — Панель управления
/components/     — Компоненты системы
/core/           — Ядро системы
/includes/       — Библиотеки (Smarty, jQuery, TinyMCE, PHPMailer и др.)
/languages/      — Языковые файлы
/modules/        — Модули
/plugins/        — Плагины
/templates/      — Шаблоны
/upload/         — Загруженные файлы
```

## Разработка

- Ветка `develop` — рабочая; `master` — стабильная.
- Исходный проект: https://github.com/instantsoft/icms1 — используется как `upstream`.

```bash
git clone https://github.com/myinstantcms/icms1.git
cd icms1
git checkout develop
git remote add upstream https://github.com/instantsoft/icms1.git
```
