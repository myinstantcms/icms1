## 2. Совместимость с PHP 8.3

### 2.1 Фатальные parse-ошибки (5 файлов)

| Файл | Причина | Функциональность, которая падает |
|---|---|---|
| `core/classes/jevix.class.php` (7 вхождений, строки ~1437+) | смещения строк `$c{0}` — **удалены в PHP 8.0** | **Jevix — HTML-фильтр всего пользовательского контента** (критично: без него ломается и анти-XSS цепочка) |
| `core/classes/idna_convert.class.php` (4 вхождения, строка 421+) | `$encoded{$k}` | punycode-конвертация IDN-доменов |
| `plugins/p_kcaptcha/codegen/kcaptcha.php` (строка 40) | `$allowed_symbols{mt_rand(...)}` | генерация kcaptcha |
| `includes/excel/excel_reader2.php` (строка 907) | `$this->_ole =& new OLERead();` — `=& new` не парсится в PHP 8 (плюс `split()` в строках 79, 835 — удалён в 7.0) | импорт Excel в админке каталога (`admin/components/catalog/backend.php`) |
| `admin/applets/userbanlist.php` (строка 79) | **Регрессия самого форка**: коммит `91e3e8a` (замена `create_function`) оставил лишнюю `)` — `})));` вместо `}));` | апплет «Бан-лист пользователей» в админке |
| `components/users/files.php` (строка 223) | `$post_max_b{...}` | страница загрузки файлов пользователя |

### 2.2 Runtime-фатальные вызовы (срабатывают по ветке)

| Место | Проблема | Когда падает |
|---|---|---|

### 2.3 Риски уровня deprecation (не блокируют 8.3, но зашумляют логи и сломаются на 8.4+)

- Динамические свойства классов (deprecated 8.2) — кодовая база написана до PHP 8, классы ядра наверняка создают свойства на лету; подтверждается рантайм-тестированием.
- Неявно nullable-параметры `function f(Type $x = null)` (deprecated 8.4) — есть в legacy-библиотеках.
- Передача `null` в не-nullable параметры встроенных строковых функций (deprecated 8.1) — типично для старого кода.

**Вывод:** после точечных фиксов §2.1–2.2 (~15 строк в 7 файлах) система Syntax-совместима с PHP 8.3. Для полной гарантии нужен прогон под веб-сервером с `error_reporting=E_ALL`.

## 3. Безопасность

### 3.1 Критичные

| K2 | **`unserialize()` пользовательской cookie** `geodata` — PHP Object Injection | `core/classes/geo.class.php:45` | Заменить на `json_encode/json_decode` (и в месте записи cookie тоже); как минимум — `allowed_classes: false` |

## 5. Оптимизация

1. **Удалить мёртвый код**: `includes/swfupload/` (Flash, ✅ удалён), `includes/excel/` — после решения по каталогу. Меньше поверхности атаки и размера дистрибутива.
2. **Smarty**: включить `$smarty->compile_check = false` в продакшене (пересборка шаблонов на каждый запрос), `$caching` для тяжёлых страниц — проверить текущие значения в `core/cms.php`.
3. **OpCache**: убедиться, что на проде `opcache.validate_timestamps=0` при деплое с прерывом кеша.
4. **Composer**: директория без composer.json — библиотеки вручную в `includes/`. Для управляемости обновлений (§4) стоит завести `composer.json` с репозиторием библиотек в `includes/` (постепенная миграция).
5. **Динамические свойства**: при переходе на PHP 8.2+ добавить `#[\AllowDynamicProperties]` либо декларации свойств в ядре — уберёт тысячи deprecation-notice и разгрузит логи.
